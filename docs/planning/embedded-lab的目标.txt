----------------------------------------------------------
目标：
	不是 "买几块开发板、学几个协议"
	而是 "一个长期、统一、可逐步扩展的个人嵌入式实验平台"
	
	总结：建立一套可长期维护和扩展的嵌入式学习与实验平台，
	用同一套硬件体系系统练习 MCU 底层机制、常用通信协议、事件驱动框架、RTOS、网络协议以及调试分析能力，
	并最终能够独立完成一个接近真实产品形态的嵌入式系统。
	
	也就是说未来 板子可用换，但实验体系、学习方法、代码结构 和 测试思路应该一直保留下来
	
	我们要达到：
	我知道它为什么存在 --> 我知道底层怎么工作 --> 我能自己配置和驱动 --> 我能用仪器验证它 --> 我能制造故障并定位 --> 我能把它放进不同的软件架构 --> 我知道什么时候应该用它

	最终我们的嵌入式系统体系：
                    Embedded System
                           │
        ┌──────────────────┼──────────────────┐
        │                  │                  │
     MCU底层机制         通信能力           软件架构
        │                  │                  │
     GPIO               UART             Super Loop
     Timer              I2C              Protothreads
     Interrupt          SPI              EventOS Nano
     DMA                CAN              QP-nano
     NVIC               USB              FreeRTOS
     Clock                               ChibiOS
                                         Zephyr
        │                  │                  │
        └──────────────────┼──────────────────┘
                           │
                       TCP/IP / MQTT
                           │
                           ▼
                  一个完整嵌入式设备
	
	最终达到的能力：
	拿到一套新的MCU硬件和芯片手册，能够自己建立工程、配置时钟和GPIO、
	写中断和DMA、驱动 UART/I2C/SPI/CAN/USB
	使用逻辑分析仪定位通信问题
	根据项目需求选择 裸机、事件驱动、FreeRTOS、ChibiOS 或 Zephyr
	让设备通过 MQTT 与 Linux 主机通信
	
	原则："所有实验都尽量做到 可观察、可测量、可故障注入、可复现"
	不只满足 程序运行成功
	而是明白：为什么成功？逻辑分析仪看到什么？寄存器是什么状态？中断什么时候发生？DMA什么时候完成？出现各种异常时会发生什么以及怎么应对？
	
	"嵌入式系统实验平台" 最终覆盖 MCU基础：
	中断/Timer/DMA、 UART/I2C/SPI、 CAN/USB、 Protothreads、 EventOS Nano、 QP-nano、 FreeRTOS、 ChibiOS、 Zephyr、 TCP/IP、 MQTT、 综合嵌入式系统
